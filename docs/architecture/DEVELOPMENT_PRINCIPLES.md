# ROLO 最高开发准则

状态：规范性文档  
适用范围：所有代码、Contract、Schema、Adapter、Agent、文档、测试、CI 和发布变更

## 一、最高原则

**先交付一个可在新环境中运行的、可验证的纵向闭环，再扩展横向能力。**

任何功能只有同时满足“能安装、能运行、能观察、能验证、能失败关闭、能复现”时，才算
完成。代码量、Operation 数量、模型能力和界面完成度都不能替代一个可运行的闭环。

ROLO 的默认产品承诺是：新开发者在具备明确列出的前置条件时，**10 分钟内完成安装并跑通
离线 Demo**。这个 Demo 必须不依赖真实机器人、不依赖付费 API、不依赖网络运行时服务，且
能够展示从输入到结果的真实产品路径。真实机器人和 Agent 的能力必须在此基础上作为独立
扩展验证，不能改变 Demo 的确定性。LeRobot 集成测试属于独立的真实开源工程验收，不得把
其 PyTorch、相机或硬件依赖偷偷加入基础测试环境。

当前 P0 工具链固定支持 Python 3.10、3.11、3.12 和 3.13；仓库 `.python-version` 固定本地
默认解释器为 3.10，CI 必须对四个版本执行完整 lint 和测试。Lerobot（
[`huggingface/lerobot`](https://github.com/huggingface/lerobot)）作为后续真实机器人/数据集
集成验证对象，不能成为 P0 离线 Demo 的隐式依赖。

## 二、不可妥协的开发顺序

所有较大变更按以下顺序设计和验收：

1. **先定义纵向切片**：明确用户输入、状态变化、产物、失败条件和验收命令。
2. **先打通最小闭环**：优先实现一个真实可调用的端到端路径，不先铺开全部抽象。
3. **再增加证据**：每次执行都必须能回答使用了什么输入、发生了什么、得到什么结果、
   哪些事实已确认、哪些仍未知。
4. **再增加安全边界**：写操作、敏感数据、R2/R3 操作必须有显式授权、超时、取消或回滚，
   失败时拒绝执行。
5. **再扩大兼容面**：增加第二个独立 Adapter 或目标平台，证明公共语义而不是只证明单一
   实现。
6. **最后优化体验和规模**：Web 工作台、更多 Operation、模型增强和性能优化必须建立在
   已验证的闭环之上。

## 三、完成定义（Definition of Done）

一个功能或阶段只有在以下条件全部成立时才能标记完成：

- 有一条从用户输入到结果的可执行命令或测试；
- 有成功路径、失败路径和至少一个边界路径；
- 产物有版本化 Schema、来源、完整性摘要和明确限制；
- 运行结果不依赖未声明的本机状态、密钥或网络服务；
- 变更不把静态声明升级为运行时事实，不把命令接受升级为物理成功；
- 对写操作定义取消、补偿或回滚，并验证拒绝路径；
- 本地和 CI 使用同一条验收命令；
- 文档中的命令、路径和输出与当前实现一致；
- 至少一个新环境可以按 Quickstart 在 10 分钟内复现；
- 若功能尚未满足以上条件，必须标为 `DRAFT`、`EXPERIMENTAL` 或 `BLOCKED`，不能用
  “已支持”描述。

## 四、ROLO 的优先级判断

发生取舍时，按以下优先级决策：

1. 确定性安全边界和失败关闭；
2. 可复现的纵向闭环；
3. 证据完整性和可审计性；
4. 真实机器人/多平台互操作；
5. 测试、CI、发布和回滚能力；
6. 性能、界面和功能广度。

因此，**不以新增 294 个 Operation、增加模型提示词或制作 UI 作为优先交付目标**，除非
它们直接改善当前纵向闭环的可验证性。

## 五、阶段性硬要求

### Probe

必须完成 `TargetProfile → SSH Connector → TargetEvidenceBundle → NativeToolSession →
ToolPlan → Conformance` 的可验证路径。Probe 只证明目标事实、工具边界和通路存在，
不宣称物理行为正确或安全。

### Trace / Certify

本轮只保留阶段契约和读取入口，不实现诊断、过程追踪、验收或回归业务。未来实现必须
继续消费 Probe 的目标身份、Evidence、Session、allowlist 和 digest，不能绕过这些门禁。

### Episode

每次有意义的执行都应保留可回放的输入、命令、状态、遥测/外部观察、版本指纹、判定和
限制。Episode 不完整时必须显式标记缺失，不能伪造完整闭环。

## 六、对 Pull Request 和发布的要求

每个 PR 描述必须回答：

- 这次变更打通了哪条纵向路径？
- 新环境如何在 10 分钟内复现？
- 成功、失败和边界测试在哪里？
- 哪些能力仍是模拟、静态发现或未验证？
- 对安全、权限、数据分类和回滚有什么影响？

发布前必须保留 Quickstart 验收记录。无法安装、无法运行、无法验证或无法解释失败的
版本，不得作为稳定版本对外宣传。
